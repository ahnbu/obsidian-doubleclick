## C. 문제

1. **Windows 코드는 맥에서 재사용할 수 없다.** 레지스트리, `user32` 창 제어, `ShellExecuteW`가 모두 Win32 API다. 재사용할 수 있는 것은 로직(볼트 찾기, URI 만들기, Advanced URI 감지, 폴백 순서)뿐이다.
2. **맥에서 더블클릭은 argv가 아니라 Apple Event(`odoc`)로 온다.** 앱 번들이 `NSApplicationDelegate`로 받아야 하므로, 명령줄 바이너리 하나로는 받을 수 없다.
3. **맥 특유의 경로 함정**이 있다.
   - 한글 파일명의 NFC/NFD(유니코드 정규화: 같은 글자를 조합형·분리형으로 저장하는 차이)
   - 대소문자를 구분하지 않는 APFS
   - `/private` 심볼릭 링크
4. **서명·공증이 없으면 다운로드한 앱을 Gatekeeper가 막는다.** macOS 15부터는 우클릭 → 열기 우회도 없어졌다.

### 검토한 방식과 기각 근거

| 방식 | 판정 | 근거 |
|---|---|---|
| **Swift AppKit 앱** | ✅ 채택 | `odoc`를 받는다. Windows 버전과 기능이 대등하다. `swiftc`로 이 맥에서 바로 빌드된다 |
| AppleScript/Automator 앱 | ❌ 기각 | 포럼에 이미 같은 방식이 있다(lzilioli #125, megclaypool Gist). 공개할 차별점이 없고 인코딩·NFC 처리를 테스트하기 어렵다 |
| Go darwin 빌드 | ❌ 기각 | Go만으로는 `odoc`를 받을 수 없어 cgo와 Cocoa 브리지가 필요하다. 이 맥에 Go도 없다 |
| 애플 공증(연 99달러) | ⏸ 보류 | 비용과 가입 절차가 사용자 결정 사항이다. 이번에는 미서명(ad-hoc 서명) 배포에 README 안내를 붙인다. Windows 버전도 미서명이라 조건이 같다 |

| 로그 | `~/Library/Logs/obsidian-doubleclick.log`. 줄 앞에 UTC 시각(`2026-09-28T03:30:00Z `)을 붙이고, 본문 형식은 Windows와 맞춘다: `LAUNCH obsidian-uri uri_mode=(adv-uri\|official) <URI 전문>` / `LAUNCH fallback-config <앱>` / `LAUNCH fallback-detected <번들 ID>` / `WARN <사유>` |

### build.sh

1. `tests/CoreTests.swift` + `Core.swift`를 컴파일해 실행한다. 하나라도 실패하면 중단한다.
2. 유니버설 바이너리를 만든다. `swiftc -O -target arm64-apple-macos12`와 `-target x86_64-apple-macos12`로 각각 빌드한 뒤 `lipo`로 합친다. x86_64 SDK가 없어 실패하면 arm64 전용으로 진행하고 README에 적는다.
3. `macos/build/ObsidianDoubleclick.app`을 조립하고 `codesign --force --deep -s -`로 ad-hoc 서명한다.
4. `ditto -c -k --keepParent`로 `macos/build/obsidian-doubleclick-macos.zip`을 만든다.
